1. 架构总览

整套手法 = 分层架构 + 关注点分离。依赖方向单向向下，同层页面之间互不引用，跨页面通信走事件总线。对应 qfluentwidget 官方（gallery / clock 示例）的组织方式。

main.py
启动入口
↓
main_window.py
组装层（注册）
↓
xxx_interface.py
页面逻辑（Presenter）
↓
Ui_XxxInterface.py
界面定义（View）
signal_bus.py
constants.py
components/
公共层/组件层：被上层任意引用
🔒 依赖铁律：import 方向只能从上往下。页面禁止 import 其他页面或组装层；组装层禁止写业务逻辑；Ui_ 文件禁止出现任何"动作"。

3. 启动时序

程序从 python main.py 到界面可交互，依次发生：

# 1) main.py：创建 QApplication + MainWindow
w = MainWindow()

# 2) MainWindow.__init__ 内，按顺序：
#    ① 搭建侧边栏骨架（标题行 / 中部菜单区 / 弹性留白 / 底部区）
#    ② 搭建右侧容器（折叠后展开按钮行 + QStackedWidget）
self.homeInterface = HomeInterface()        # ③ 实例化页面
#    └─ HomeInterface.__init__ 内部：
#       super().__init__(parent)  -> QWidget 初始化（MRO 跳过 Ui_）
#       self.setupUi(self)        -> 创建全部控件并摆放
#       self.btnClick.clicked.connect(...) -> 挂业务逻辑
self.addInterface("首页", self.homeInterface) # ④ 注册：入堆栈 + 生成导航按钮 + 绑定切换

# 3) w.show() 后，用户点击导航按钮 -> stacked.setCurrentIndex(i) 切换页面
⚠️ 时序陷阱（PyQt6 6.11 + Python 3.14 会因此原生崩溃）：构造期间若调用会触发信号的方法（如 setChecked(True) 触发 toggled），必须确保被触发的槽函数依赖的所有控件已经创建完毕（setupUi 之后、控件创建之后），并在槽函数内加 hasattr 防御。

4. 各层详解

4.1 入口 main.py —— 最薄的一层

职责：创建 QApplication、导入组装层、显示。不写任何组装或业务。

import sys

from PyQt6.QtWidgets import QApplication

from app.view.main_window import MainWindow


if __name__ == "__main__":
    app = QApplication(sys.argv)
    w = MainWindow()
    w.show()
    sys.exit(app.exec())

4.2 组装层 main_window.py —— 注册式导航

职责：搭建侧边栏骨架、维护 QStackedWidget、用 addInterface 注册页面、折叠/展开。零业务逻辑。

class MainWindow(QMainWindow):
    def __init__(self):
        super().__init__()
        # ... 窗口尺寸、常量、侧边栏骨架、右侧容器 ...

        # 先存实例属性，再注册（与 qfluentwidget 一致）
        self.homeInterface = HomeInterface()
        self.dataInterface = DataInterface()
        self.settingInterface = SettingInterface()
        self.interface_btns: list[QPushButton] = []
        self.addInterface("首页", self.homeInterface)
        self.addInterface("数据管理", self.dataInterface)
        self.addInterface("设置", self.settingInterface, position="bottom")
        self.stacked.setCurrentIndex(0)

    def addInterface(self, text: str, widget: QWidget, position: str = "top") -> int:
        """注册：入 QStackedWidget + 生成导航按钮 + 绑定切换，返回页面索引"""
        index = self.stacked.addWidget(widget)
        btn = QPushButton(text)
        btn.setFixedHeight(self.menu_btn_height)
        # ... 按 position 应用 top/bottom 样式，加入 menu_area / bottom_area ...
        btn.clicked.connect(lambda _, i=index: self.stacked.setCurrentIndex(i))
        self.interface_btns.append(btn)
        return index
🔒 main_window 里禁止出现 setText、操作列表、弹窗等业务动作。它只做：建页面实例 → 注册 → 折叠展开。

4.3 Ui_* 界面定义层 —— 只画界面

pyuic 风格：object 基类 + setupUi/retranslateUi。结构与 Qt Designer 导出一致，控件名 camelCase，是界面层与逻辑层的唯一约定接口。

class Ui_HomeInterface(object):
    def setupUi(self, HomeInterface: QWidget):       # 参数必须注解
        HomeInterface.setObjectName("HomeInterface")
        HomeInterface.setStyleSheet(f"background:{PAGE_BACKGROUNDS[0]};")

        self.verticalLayout = QVBoxLayout(HomeInterface)
        self.verticalLayout.setContentsMargins(20, 20, 20, 20)
        self.verticalLayout.setSpacing(12)

        # 标题 + 副标题
        self.titleLabel = QLabel(HomeInterface)
        self.titleLabel.setStyleSheet(TITLE_STYLE)
        self.verticalLayout.addWidget(self.titleLabel)

        # 业务控件（逻辑层通过 self.xxx 访问）
        self.lblCount = QLabel(HomeInterface)
        self.btnClick = QPushButton(HomeInterface)
        self.btnClick.setFixedSize(110, 36)
        # ... 布局 addWidget ...

        self.verticalLayout.addStretch()
        self.retranslateUi(HomeInterface)

    def retranslateUi(self, HomeInterface: QWidget):
        self.titleLabel.setText("首页")
        self.btnClick.setText("点我 +1")
        self.lblCount.setText("点击次数：0")
🔒 Ui_ 文件里禁止出现：clicked.connect、if 业务判断、signalBus、任何"动作"。它只创建控件 + 摆放 + 初始文本。

4.4 页面逻辑层 *_interface.py —— 多重继承 + 逻辑

核心手法：class XxxInterface(Ui_XxxInterface, QWidget) 多重继承。MRO 顺序：XxxInterface → Ui_XxxInterface → QWidget → QObject。因为 Ui_ 类没有定义 __init__，super().__init__(parent=parent) 会自动跳过 Ui_ 直达 QWidget.__init__。

class HomeInterface(Ui_HomeInterface, QWidget):
    def __init__(self, parent: QWidget | None = None):
        super().__init__(parent=parent)   # MRO 跳过 Ui_，直达 QWidget
        self.setupUi(self)                 # 安装界面（创建全部控件）

        # 之后直接操作 UI 控件 + 挂逻辑
        self.count = 0
        self.btnClick.clicked.connect(self._on_click)
        signalBus.data_added.connect(self._on_data_added)

    def _on_click(self):
        self.count += 1
        self.lblCount.setText(f"点击次数：{self.count}")

    def _on_data_added(self, text: str):
        if not hasattr(self, "lblLast"):   # 防御：槽内异常会原生崩溃
            return
        self.lblLast.setText(f"最近添加：{text}")
🔒 页面禁止 import 其他页面/组装层；只依赖自己的 Ui_、app.common.*、app.components.*。

两个页面互不引用，只通过信号总线这个"中间人"对话。新增信号 = 在 SignalBus 类里加一行 pyqtSignal(...)。

class SignalBus(QObject):
    data_added = pyqtSignal(str)   # 参数类型 str
    data_cleared = pyqtSignal()      # 无参数

signalBus = SignalBus()              # 全局单例，各文件 import 同一个实例

8. 反模式详解（"乱来"的样子）

❌ 把逻辑写进 Ui_ 文件（最常见）

症状：Ui_HomeInterface.py 里出现 clicked.connect、if、signalBus。

危害：界面与逻辑耦合，改逻辑要动界面定义；pyuic 重新生成会覆盖掉你写的逻辑；两个职责挤在一个文件里，读起来乱。

正确：Ui_ 只 addWidget 和 setText；所有 connect 和判断进 *_interface.py。

❌ 页面直接 import 另一个页面

症状：from app.view.data_interface import DataInterface 出现在 home_interface.py 里，直接调对方的方法拿数据。

危害：两个页面强耦合——改一个必查另一个；形成循环 import 风险；测试无法单独跑一个页面。

正确：数据页 signalBus.data_added.emit(text)，首页 signalBus.data_added.connect(...)。

❌ main_window 里掺业务

症状：组装层里写 self.homeInterface.lblCount.setText(...)、页面按钮的槽函数定义在 main_window 里。

危害：组装层膨胀，页面自治被破坏；换个页面组合方式时业务逻辑被一起搬走。

正确：组装层只做"建实例 + 注册 + 折叠"三件事。

❌ 页面继承 QMainWindow / 自建窗口

症状：页面类写 class HomeInterface(QMainWindow) 或自己 resize、setWindowTitle。

危害：页面是内容，不是窗口；多页面会变成多窗口，导航切换失效。

正确：页面一律 QWidget；全应用只有一个 MainWindow。

❌ 忘了 setupUi / 忘存实例属性

症状：构造里没调 self.setupUi(self) → 控件全是 None，一访问就崩；或 addInterface("首页", HomeInterface()) 没先存 self.homeInterface → 后续拿不到页面实例。

正确：构造里 super().__init__ 后立即 setupUi；先 self.homeInterface = HomeInterface() 再注册。

❌ 手写 Ui_ 漏参数注解 / 空集合不带类型

症状：basedpyright 报 reportUnknownMemberType。

正确：def setupUi(self, HomeInterface: QWidget)；self.btns: list[QPushButton] = []。

9. basedpyright 红线（0 error / 0 warning）

配置在根目录 pyproject.toml 的 [tool.basedpyright]。写代码时直接遵守，不要写完再靠检查修：

红线正确写法
不留未使用的 import（error）import 了就要用，否则删掉
函数/方法参数全注解parent: QWidget | None = None、index: int、item: QListWidgetItem、槽函数 *_args: object
空集合带类型self.nav_btns: list[QPushButton] = []、parts: list[str] = []

PyQt6 6.11 + Python 3.14 原生崩溃坑

信号槽函数内抛出 Python 异常 → 进程直接崩溃（退出码 -1073740791，无任何报错，faulthandler 也抓不到）。防御三招：

  1. 槽函数开头 hasattr / try-except 防御；
  2. 构造期间会触发信号的方法（setChecked(True) 等）放在依赖控件创建之后；
  3. 遇到"无故崩溃无报错"，优先怀疑信号槽内异常，用 QT_QPA_PLATFORM=offscreen + 逐段构造二分定位。

11. FAQ

Q：为什么 super().__init__(parent=parent) 不会调 Ui_ 的构造？

MRO 是 XxxInterface → Ui_XxxInterface → QWidget → QObject。super() 找下一个定义了 __init__ 的类；Ui_XxxInterface(object) 没定义 __init__，所以被跳过，直达 QWidget.__init__。这是 Ui/Interface 分离能成立的关键。

Q：Ui_ 文件能可视化编辑吗？

能。在 Qt Designer 里画 .ui → pyuic6 xxx.ui -o Ui_XxxInterface.py 重新生成（逻辑文件不用动）。生成的 Ui_ 若触发 basedpyright 报错，用文件级 # pyright: 豁免，别手改。

Q：三个模板有什么区别，新页面用哪个？
模板页面组织入口
left_side_nav_layout页面继承 BaseInterface（基类给骨架）demo.py
left_side_nav_ui_layoutUi_ 定义 + Interface 逻辑分离（本手册主推）main.py
top_nav_tabs_layout单文件 + QTabWidgetmain.py

新页面推荐一律按第 6 节 Checklist 走 Ui/Interface 分离。

Q：跨页面通信除了 signalBus 还有别的吗？

小型项目用 signalBus 足够（发布-订阅解耦）。页面需要主动拉数据时，可让组装层持有页面引用做中介（组装层是唯一允许认识所有页面的地方），但不要页面间直接引用。
